# Установка хоста через disko и nixos-anywhere

Инструкция для произвольного хоста этого flake. Все локальные команды
выполняются в Bash на доверенной машине с Nix и включёнными flakes.

**Внимание: disko полностью уничтожит данные на настроенных дисках, включая
существующие разделы и dual boot. Сделайте резервную копию и проверьте
целевую машину и каждый диск до запуска установки.**

## 1. Выбрать хост и целевую машину

Замените значения своими:

```bash
cd ~/nixdotfiles
host=myhost
target=192.0.2.10
user=myuser
```

Проверьте, что:

- Хост объявлен в `nixosConfigurations` в `flake.nix`.
- Его модуль импортирует `inputs.disko.nixosModules.disko` и свою разметку disko.
- Hardware-конфигурация соответствует целевому оборудованию и импортирована.
- Настройки загрузчика соответствуют UEFI или BIOS целевой машины.
- В установленной системе включён SSH и разрешён ваш ключ для входа.
- Целевая машина доступна по SSH как root. Поддерживается также пользователь
  с беспарольным sudo; ниже используется root.
- У целевой машины есть проводная сеть, DHCP и доступ в интернет.
  Временный установщик не наследует произвольные настройки Wi-Fi или
  статической сети исходной ОС. Для таких сетей заранее подготовьте
  подходящий установщик.

Сохраните доступ к консоли на случай потери сети. Можно загрузить целевую
машину с NixOS installer USB и включить SSH. Иначе nixos-anywhere обычно
загружает временный установщик через kexec.

## 2. Проверить диски и hardware-конфигурацию

```bash
ssh "root@$target" \
  'lsblk -o NAME,SIZE,MODEL,SERIAL,TYPE,MOUNTPOINTS; ls -l /dev/disk/by-id/; if test -d /sys/firmware/efi; then echo UEFI; else echo BIOS; fi'
```

В `hosts/<host>/disko.nix` укажите проверенные диски. Предпочитайте стабильные
пути `/dev/disk/by-id/...`. Не считайте `/dev/sda` или `/dev/nvme0n1`
автоматически правильными. Проверьте все устройства, указанные в разметке.

nixos-anywhere использует устройства из flake. Комментарии про
`disko-install --disk` не означают, что nixos-anywhere автоматически подставит
другой диск.

Если подходящая hardware-конфигурация уже импортирована, генерация не нужна.
Если её нужно получить с целевой машины, подготовьте импорт
`./hardware-configuration.nix` в модуле хоста и добавьте к команде установки:

```bash
--generate-hardware-config nixos-generate-config "hosts/$host/hardware-configuration.nix"
```

Этот вариант генерирует hardware-файл без объявлений файловых систем:
ими управляет disko. Не оставляйте одновременно конфликтующие старые
hardware-настройки. Предварительная сборка из следующего раздела возможна,
только когда импортируемый файл уже существует.

## 3. Подготовить SOPS, если хост использует секреты

Для хоста без SOPS пропустите этот раздел и используйте команду установки
без секретов ниже. Например, `demo` в этом репозитории должен оставаться
без SOPS.

Задайте пути к существующим age-ключам вне репозитория:

```bash
system_key="$HOME/keys/$host/system.key"
user_key="$HOME/keys/$host/user.key"
chmod 600 "$system_key" "$user_key"
```

Родительские каталоги должны быть доступны только доверенным пользователям.
Если файлы принадлежат root, сначала исправьте владельца с помощью sudo.
Не выводите приватные ключи и расшифрованные секреты. Не добавляйте их
в Git или Nix store.

Публичные recipients можно получить безопасно:

```bash
age-keygen -y "$system_key"
age-keygen -y "$user_key"
```

Проверьте, что recipients добавлены в соответствующие правила `.sops.yaml`
и в зашифрованные файлы. Для нового ключа обновите получателей с помощью
старого рабочего или recovery-ключа:

```bash
SOPS_AGE_KEY_FILE=/path/to/existing-working-key \
  sops updatekeys secrets/system/shared.yaml
SOPS_AGE_KEY_FILE=/path/to/existing-working-key \
  sops updatekeys "secrets/users/$user.yaml"
```

Пути выше соответствуют принятому в репозитории размещению секретов.
Проверьте `defaultSopsFile` и дополнительные `sopsFile` в модулях выбранного
хоста. Обновите и проверьте каждый используемый файл. Одного изменения
`.sops.yaml` недостаточно. Без действующего старого ключа обновить получателей
существующего файла нельзя.

Проверьте расшифровку ключами, которые будут установлены:

```bash
SOPS_AGE_KEY_FILE="$system_key" \
  sops decrypt secrets/system/shared.yaml >/dev/null
SOPS_AGE_KEY_FILE="$user_key" \
  sops decrypt "secrets/users/$user.yaml" >/dev/null
```

Продолжайте только при успешном завершении проверок. Если хост использует
только системные или только пользовательские секреты, подготовьте только
нужный ключ и опустите ненужные команды.

## 4. Проверить сборку и владельца пользовательского ключа

Новые файлы конфигурации добавьте в Git перед flake-командами:
неотслеживаемые файлы не входят в источник flake.

```bash
nix build ".#nixosConfigurations.$host.config.system.build.toplevel" --no-link
```

Сборка не проверяет расшифровку SOPS. Если локальная машина не может собрать
целевую архитектуру, используйте подходящий builder или `--build-on remote`
при установке.

Для пользовательского ключа нужны числовые UID и GID из итоговой
конфигурации. Посмотрите настройки:

```bash
nix eval --json ".#nixosConfigurations.$host.config.users.users.$user.uid"
nix eval --raw ".#nixosConfigurations.$host.config.users.users.$user.group"
```

Затем проверьте GID найденной группы:

```bash
group=users # замените результатом предыдущей команды
nix eval --json ".#nixosConfigurations.$host.config.users.groups.$group.gid"
```

Если UID или GID равен `null`, он назначается при активации. Для предсказуемой
установки пользовательского ключа задайте явные, свободные UID/GID в
конфигурации. Не предполагайте, что любой пользователь получит `1000:100`.

## 5. Установить систему

**Команды nixos-anywhere ниже запускают разрушительную разметку.
Продолжайте только после проверки резервной копии, адреса, дисков,
загрузчика, SSH-доступа и необходимых ключей. Выберите один вариант.**

### Без секретов

```bash
nix run github:nix-community/nixos-anywhere -- \
  --flake ".#$host" \
  --target-host "root@$target"
```

### С системным и пользовательским SOPS-ключами

Проверьте целевые пути `sops.age.keyFile` в NixOS и Home Manager модулях.
Ниже используются пути, принятые для пользователя `andriano` в этом
репозитории. Для другого пользователя или собственного модуля скорректируйте
пути и домашний каталог.

Замените UID/GID проверенными значениями из предыдущего раздела:

```bash
uid=1000
gid=100
umask 077

stage=$(mktemp -d)
trap 'rm -rf "$stage"' EXIT

install -D -m600 "$system_key" \
  "$stage/var/lib/sops-nix/key.txt"
install -D -m600 "$user_key" \
  "$stage/home/$user/.config/sops/age/keys.txt"
```

Обе команды `install` должны завершиться успешно. Только затем запускайте:

```bash
nix run github:nix-community/nixos-anywhere -- \
  --flake ".#$host" \
  --target-host "root@$target" \
  --extra-files "$stage" \
  --chown "/home/$user/.config/sops" "$uid:$gid"
```

Если нужен только системный ключ, не копируйте пользовательский ключ
и опустите `--chown`. Если нужен только пользовательский ключ, не копируйте
системный ключ.

`--extra-files` переносит файлы в смонтированную целевую систему после disko
и до `nixos-install`. Ключи не требуется заранее копировать в live-систему.
`--disk-encryption-keys` служит другой цели: передаче ключей разблокировки
диска установщику, а не сохранению SOPS-ключей в установленной системе.

При необходимости добавьте `--generate-hardware-config` из раздела 2
или `--build-on remote`. nixos-anywhere устанавливает систему и по умолчанию
перезагружает целевую машину.

После завершения удалите временную копию ключей:

```bash
rm -rf "$stage"
trap - EXIT
```

Исходные ключи сохраняются. Храните отдельную защищённую резервную копию.

## 6. Проверить установленную систему

После перезагрузки адрес может измениться из-за DHCP. Используйте учётную
запись и SSH-ключ, разрешённые установленной конфигурацией. Доступ root
после установки не гарантируется.

```bash
ssh "$user@$target"
```

На установленной машине:

```bash
passwd
systemctl --failed
```

Смените временный пароль, если он задан. Для хоста с пользовательским SOPS:

```bash
systemctl --user status sops-nix.service
```

Если SSH сообщает о смене host key, сначала проверьте новый отпечаток через
доверенную консоль целевой машины. Только после проверки удалите старую
запись на локальной машине и подключитесь снова:

```bash
ssh-keygen -R "$target"
ssh "$user@$target"
```
